\section{Motivation}
\label{sec:motivation}

Traditional cloud architectures often rely on full-fledged virtual machines or containers, which, while
flexible, come with significant overhead in resource consumption, boot time, and security exposure.
In contrast, unikernels offer a lightweight option that dramatically reduces the attack surface and simplifies deployment. \\
\\
Despite these advantages, unikernels remain underused compared to conventional cloud architectures. Therefore, as Unikraft currently
lacks gaming-related projects, it makes this an ideal opportunity to validate the viability of unikernels in a performance-critical domain. \\
\\
Gaming is a globally popular and technically demanding field, often serving as a benchmark for responsiveness and scalability.
Demonstrating that Unikraft can handle such workloads opens doors for broader adoption. \\
\\
Furthermore, the project allows for a technical evaluation between Unikraft's binary compatibility mode and native mode, offering insights into the
trade-offs between rapid porting and optimal performance. The benchmarks and results from this work could serve as reference points for future
porting efforts. \\
\\
Ultimately, promoting the use of unikernels in gaming has the potential to elevate the visibility of projects like Unikraft. It can help showcase
the practical value of unikernels to a wider audience - including developers, researchers, and companies - which in turn could spark increased interest,
community contributions and industry investment in unikernel-based systems.


\section{Objectives}
\label{sec:objecties}

The key objectives of this thesis are:
\begin{itemize}
    \item Run an OpenArena server from scratch (source files).
    \item Port the server to Unikraft in binary compatibility mode using the existing libelf library and a Dockerfile-based root filesystem.
    \item Port the server to Unikraft in native mode by creating an external library containing the required source files and dependencies.
    \item Perform benchmarks to compare the two approaches.
\end{itemize}

\section{Use Cases}
\label{sec:usecases}

\subsection{Main Use Case}
\label{subsec:mainusecases}
The main objective of this project is to successfully run an OpenArena server on Unikraft, enabling real-time multiplayer gameplay by allowing clients to connect and interact. This demonstrates
the capability of Unikraft to support complex, interactive applications.

\subsection{Other Use Cases}
\label{subsec:otherusecases}
This work is also an initial step toward integrating gaming workloads on Unikraft. By showcasing the feasibility of running a game server on Unikraft, the project lays the groundwork for future
research and development in this area.
