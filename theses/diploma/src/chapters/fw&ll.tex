\section{Conclusion}
Wrapping up, this project successfully manages to extend the horizon of applicability of Unikraft unikernels: gaming servers. \\ \\
Throughout the thesis, the OpenArena server has been ported to Unikraft using all available methods, with detailed descriptions of required files
during the build and run phases:
\begin{itemize}
    \item Binary compatibility mode, thanks to the design of Unikraft which permits running Linux binaries on top of it. Here,
    the ELF Loader has a significant job during runtime: load the server into memory and schedule it for execution;
    \item Native compatibility mode, where the kernel is built using first principles tools. It is defined by the fine control over the
    build phase.
    \item External Unikraft library, which aligns with the philosophy of Unikraft: modular and reusable components.
\end{itemize}
On a different note, working on this offered valuable experience with open-source projects as both OpenArena and Unikraft stay under this umbrella.
Moreover, it has been a real challenge to understand already built infrastructure, to adapt to it, and to improve it for the sake of the objectives. 
\section{Future Work}
Now that an initial effort to integrate gaming servers into unikernels has been made, many possibilities have arisen. \\ \\
For example, OpenArena uses an old version of OpenGL (1.3). A natural step forward would be to target games that use newer, more complex versions.
This would imply less work if the game is written in C as Unikraft is primarily based on C. \\ \\
Another interesting idea is to aim porting games developed using nowadays frameworks: Unity\footnote{\url{https://unity.com/}}, Unreal Engine\footnote{\url{https://www.unrealengine.com/en-US}} or
Godot Engine\footnote{\url{https://godotengine.org/}}. However, it would take the work required to another level due to runtime requirements or toolchain dependencies.
