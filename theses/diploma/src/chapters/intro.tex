\section{Unikernels and Unikraft}
\label{sec:uks}

Unikernels\footnote{\url{https://wiki.xenproject.org/wiki/Unikernels}} are specialized, single-address-space operating systems that seem to be more appealing when compared to well-known alternatives regarding security, size, and performance.
Their philosophy lies in eliminating unnecessary components of a kernel, keeping only the useful modules, required to run a specific application. \\ \\
Often associated\footnote{\url{https://unikraft.org/docs/concepts}} with containers and virtual machines, these promise better resource efficiency\footnote{\url{https://unikraft.org/docs/concepts/efficiency}} and security\footnote{\url{https://unikraft.org/docs/concepts/security}} due to their minimalistic nature.
Therefore, these results\footnote{\url{https://unikraft.org/docs/concepts/performance}} highlight the potential of unikernels as the future in cloud computing and edge computing environments. \\ \\
In this context, Unikraft\footnote{\url{https://unikraft.org/}} emerges as an open-source community that believes in the strengths of unikernels.
This community project employs to automate the build process of unikernels, providing at the same time modular, reusable components that are highly customizable, based on users preferences.

\section{Virtualization and QEMU}
\label{sec:virtqemu}
Virtualization\footnote{\url{https://www.ibm.com/think/topics/virtualization}} is a technology which permits to run multiple operating systems on the underlying hardware\footnote{\url{https://www.cherryservers.com/blog/virtualization-vs-containerization}}, facilitating isolation, security, and efficient usage of physical resources.
\fig[scale=0.3]{./src/img/virtualization.png}{img:virtualization}{Example of architecture for virtualization}
\\
QEMU\footnote{\url{https://www.qemu.org/}} (Quick EMUlator) is an open source, cross-platform, system emulator and virtualizer. It supports multiple host architectures, including x86 and ARM, and operating systems, such as Linux OS, macOS, and Windows. \\
\\
QEMU system emulation offers a virtual model of a machine (processing units, memory storage and external devices) to run a guest OS and it is sometimes paired with other virtualization solutions, namely hypervisors\footnote{\url{https://www.vmware.com/topics/hypervisor}}, for
better performance.
\\
\\
Emulation uses a technique named dynamic translation\footnote{\url{https://www.qemu.org/docs/master/devel/tcg.html}}\footnote{\url{https://xilinx-wiki.atlassian.net/wiki/spaces/A/pages/821395464/QEMU+User+Documentation}}
where the guest instruction set is converted on the fly into the equivalent host machine instructions and run locally, to have then the results mapped back.

\section{GNU make and Kconfig}
GNU make\footnote{\url{https://www.gnu.org/software/make/manual/make.html}} is a build automation tool used to compile software components of a project.
It defines a set of rules, dependencies and commands that specify how to transform source code into executable programs or other targets\footnote{\url{https://blog.devgenius.io/makefiles-a-practical-guide-techniques-and-templates-d7d99047bf63}}.
\\
\fig[scale=0.3]{./src/img/make.png}{img:make}{General structure of a Makefile}
\\
Kconfig\footnote{\url{https://docs.kernel.org/kbuild/kconfig-language.html}} is a configuration system originally developed for the Linux kernel. It is designed to manage complex build-time options.
Also, it provides a structural way to define configuration menus, and dependencies, allowing users to customize features through tools like \textit{menuconfig}.
\\
\fig[scale=0.3]{./src/img/kconfig.png}{img:kconfig}{Kconfig menu interface}
\\
Using these two mechanisms, the process of gluing components together to create unikernels becomes much more structured, intuitive, and, above all, easier.
\section{OpenArena}
\label{sec:openarena}

OpenArena\footnote{\url{https://openarena.ws/smfnews.php}} is an open-source game that was released in 2005.
It belongs to the category of multiplayer first-person shooters, presenting a client-server design while being written in C\footnote{\url{https://github.com/OpenArena/engine}}.
It is forked from the Quake III arena engine, initially developed by id Software. OpenArena retains most of the mechanics but adds unique characteristics driven by community development. \\ \\
As mentioned, OpenArena is built based on the client-server architecture. It allows players to create and host game servers, join remote lobbies, and, most importantly, modify the game easily
thanks to the modular approach. It supports game modifications, allowing custom characters, new maps, and gameplay tactics to be added. \\ \\
The game code, composed of textures, sounds, and configurations, is packaged into .pk3\footnote{\url{https://doomwiki.org/wiki/PK3}} files. Therefore, it is easy to bring together and share custom content. \\ \\
Given that the game appeared two decades ago, it remains, surprisingly, actively played today, particularly within niche gaming groups and enthusiasts of classic arena shooters.
