\chapter{Testing}
Until now, diverse methods of integrating an OpenArena server have been detailed, but the testing part has yet to be tackled.
It plays a significant role in ensuring the correctness of the implementations.
\section{Introducing OpenArena Client}
Given that OpenArena has a client-server design, it is important to briefly explain the client side as well for a rounded understanding of the infrastructure. \\ \\
The OpenArena client is primarily represented by the audio and video graphics rendering libraries. Its core library is OpenGL\cite{opengl}, but
an old version is used. \\ \\
As the server runs in a virtual environment provided by KVM/QEMU and the clients run locally, networking configuration is mandatory. Therefore, the server-side
uses bridging to enable the guest system to appear on the same network as the host. This is achieved by setting up a bridge interface and attaching the unikernel
network interface to it, similar to what the figure\cite{kvm-virtual-bridge} below suggests.

\section{Gameplay Simulation}
A solution for testing the server is interacting with the clients, so-called game players.\@
To achieve it, a Python script has been used to simulate a gameplay environment, which leverages the Pexpect module.\@
Pexpect spawns child applications and controls them like a human typing commands. \\ \\
Therefore, the script creates a thread for each client and employs Pexpect to generate the OpenArena clients.
A client stays connected for 30 seconds. During this time, it does specific actions: moves in a direction and shoots for a short amount of time.
After this, a delay time of 15 seconds takes place, and then the cycle starts again.
