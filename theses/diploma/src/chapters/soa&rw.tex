\chapter{Related Work}
\label{chapter:soa&rw}
At the moment of writing, there is no online evidence about any unikernel based on a game server. Instead, a few unikernel projects are briefly described, which
can be candidates for this job.
\section{MirageOS}
MirageOS\footnote{\url{https://mirage.io/}} is a unikernel developed OCaml programming language.
Instead of running on top of a general-purpose operating system, MirageOS applications are compiled along with only the OS components they need, resulting in a single-purpose unikernel. \\ \\
Given that it is built in OCaml, MirageOS takes advantage of type safety and functional programming.
It is a great fit for network services like DNS or VPN servers taking into consideration that performance and reliability are key. \\
However, there is a tradeoff. OCaml foundation makes it less practical for game server development.
Therefore, rewriting them in OCaml would take a lot of time. Even so, MirageOS proves how minimal and secure a unikernel can be.
\section{IncludeOS}
IncludeOS\footnote{\url{https://www.includeos.org/}} is a unikernel that focuses on running applications directly on virtual machines.
It is created in C++, meaning that a server like the OpenArena one could be ported more easily.
IncludeOS should be used in infrastructures where multiple instances run in parallel. For example, game lobbies in the case of OpenArena.
\section{OSv}
OSv\footnote{\url{https://osv.io/}} is a unikernel that tries to run unmodified applications, somehow similar with the binary compatibility mode provided by Unikraft, which will be detailed later. \\ \\
IncludeOS benefits from the fact that it is written in C++, which is much closer to the language used by most game engines. \\ \\
Despite that is not as minimal as MirageOS or IncludeOS, it is easier to integrate and can still offer performance and resource usage optimiations.
